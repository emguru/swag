Design principle

Original chunk text remains authoritative. SWAG metadata is stored separately and used exclusively for reranking. Synonyms and adjacent concepts are weighted retrieval hints — never appended to chunks and never treated as source facts.

IngestChunk text → embed → index. Profiles generated in parallel, stored as metadata.
QueryVector search → SWAG rerank → optional LLM answer. Chunks unchanged.
Default ($0)FAISS + sentence-transformers + heuristic profiles. No API key required.
ProductionQdrant + OpenAI embeddings + SWAG_PROFILE_MODE=llm or Ollama on-prem.
vs CRAGSWAG improves initial ranking. CRAG corrects after retrieval — complementary, not competing.

System overview portable

Single Python package with FastAPI demo. Deploy locally, in Docker, or on any VM/Kubernetes. No AWS dependency. Kube RAG LangGraph vendors an adapted copy for EKS.

Ingestion sequence

Profiles are generated from chunk text but stored separately. Embeddings use original text only — never synonym-expanded content. 

sequenceDiagram
  actor User
  participant Pipe as IngestionPipeline
  participant Load as Document loaders
  participant Chunk as chunking.py
  participant Prof as SWAGProfileGenerator
  participant Emb as Embedder
  participant VS as Vector store

  User->>Pipe: ingest_directory data/
  Pipe->>Load: load txt md pdf docx
  Load-->>Pipe: pages text
  Pipe->>Chunk: chunk with size overlap
  Chunk-->>Pipe: DocumentChunks

  alt SWAG_INGEST_PROFILES
    loop each chunk
      Pipe->>Prof: generate_chunk_profile
      Prof-->>Pipe: SWAGProfile metadata
    end
  end

  Pipe->>Emb: embed raw_text only
  Emb-->>Pipe: vectors
  Pipe->>VS: add chunks vectors profiles
  Pipe->>VS: save index

Query / SWAG rerank sequence

Retrieves a larger candidate pool than top-K, then reranks with production postprocessing. Missing profiles are generated inline (heuristic or LLM per SWAG_PROFILE_MODE). 

sequenceDiagram
  actor User
  participant Ret as RetrievalPipeline
  participant Emb as Embedder
  participant VS as Vector store
  participant RR as rerank_hits_with_swag
  participant Prof as profiles.py
  participant Post as postprocess.py
  participant LLM as LLM client

  User->>Ret: query question top_k
  Ret->>Emb: embed_query
  Ret->>VS: search RETRIEVAL_CANDIDATES
  VS-->>Ret: candidate chunks

  Ret->>RR: rerank_hits_with_swag
  RR->>Prof: ensure_swag_profiles
  Prof-->>RR: enriched hits
  RR->>RR: dedupe near duplicates
  RR->>RR: query profile + score alignment
  RR->>Post: noise gate diversity cap
  Post-->>RR: final top_k
  RR-->>Ret: swag_results + meta

  Ret->>Ret: retrieve_baseline for compare
  opt generate_answer
    Ret->>LLM: top 3 chunk texts
    LLM-->>Ret: answer
  end
  Ret-->>User: AnswerResult

Scoring formula

Configurable via VECTOR_WEIGHT, SWAG_WEIGHT, METADATA_WEIGHT. Adaptive blend adjusts weights per query when enabled.

flowchart LR
  V[vector_similarity] -->|0.65 default| F[final_score]
  S[swag_alignment] -->|0.30 default| F
  M[metadata_boost] -->|0.05 default| F
  F --> Q[chunk_quality multiplier]
  Q --> R[ranked results]
CategoryMultiplierNotes
primary_concept1.0×Core topic
user_intent0.90×Question intent
domain_term0.85×Domain vocabulary
business_goal0.75×Operational goals
direct_synonym0.70×Retrieval hint only
adjacent_concept0.60×Related concepts
negative_contextpenaltyFalse-match guard

API surface

POST /query and POST /compare return scores and source metadata by default. Set include_text or include_explanation to include full chunk text or SWAG match detail. The CLI demo (examples/demo.py) follows the same convention; use --verbose for ranking deltas.

MethodPathPurpose
GET/Service info, chunk count, endpoints
GET/healthLiveness
GET/configActive backends, scoring weights
POST/ingestIndex documents from data/
POST/queryRAG query — use_swag, include_text, include_explanation
POST/compareBaseline vs SWAG + swag_meta

include_textfalseInclude raw_text per hit
